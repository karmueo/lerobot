# UMI 模型部署：ONNX、TensorRT 转换与性能评估

本文使用训练好的本地 Diffusion Policy 检查点，完成模型转换、精度验证和性能评估。所有命令在仓库根目录执行。

默认示例：

- 训练模型：`outputs/train/dp_umi_v4/checkpoints/012000/pretrained_model`
- 导出目录：`outputs/export/dp_umi_v4/012000`
- 推理设置：batch=1，DDPM 100 步，每次生成 8 步动作块，保持检查点权重和采样配置。

当前导出包含**观测编码器和单步 U-Net 两个网络**。完整推理仍需要 Python、PyTorch/diffusers 调度器以及原有前后处理；尚未接入机器人在线控制入口。

## 1. 准备环境和模型

安装依赖：

```bash
uv sync --locked --inexact --extra diffusion --extra dataset --extra export --extra export-tensorrt
```

仅导出 ONNX 时可以去掉 `--extra export-tensorrt`。后续使用 `uv run --no-sync`，保留已安装的可选依赖。

TensorRT 当前支持 Linux x86-64、NVIDIA GPU 和 `tensorrt-cu12==10.13.3.*`，不支持 TensorRT 11。依赖由仓库锁定，SDK 二进制包从 NVIDIA 官方索引安装。无需安装 `trtexec`、PyCUDA 或 `onnxruntime-gpu`；ONNX 验证使用 ONNX Runtime CPU 包。

模型路径必须指向 `pretrained_model`，其中应包含模型权重、模型配置、前后处理配置及归一化统计量。不要指向训练任务根目录或 `training_state`。

以下变量供后续命令共用；转换其他模型时修改这两个路径：

```bash
MODEL_PATH=outputs/train/dp_umi_v4/checkpoints/012000/pretrained_model
EXPORT_DIR=outputs/export/dp_umi_v4/012000
EXPORT_DEVICE=cuda:0
```

多卡机器可以把 `EXPORT_DEVICE` 改为 `cuda:1` 等空闲设备。首版支持普通及相对位姿 Diffusion，保留检查点的 DDPM/DDIM 设置，不支持 ACT/VLA。

## 2. 转换 ONNX 和 TensorRT

同时生成 ONNX、TensorRT FP32 和 TensorRT FP16：

```bash
uv run --no-sync lerobot-export \
  --policy_path="$MODEL_PATH" \
  --output_dir="$EXPORT_DIR" \
  --format=both \
  --device="$EXPORT_DEVICE" \
  --trt_precision=both
```

输出目录已存在时命令会拒绝覆盖。默认示例目录已有实测产物，可直接执行第 3 节验证；需要重新构建时，选择新目录，或明确在导出命令末尾添加 `--overwrite=true`。导出目录应与源检查点分开。

| 参数              | 可选值与用途                                                                |
| ----------------- | --------------------------------------------------------------------------- |
| `--format`        | `onnx` 仅导出 ONNX；`tensorrt` 和 `both` 均先生成并保留 ONNX，再构建 engine |
| `--trt_precision` | `fp32`、`fp16`、`both`，默认 `both`                                         |
| `--device`        | 默认 `cuda:0`；仅导出 ONNX 时支持 `cpu`                                     |
| `--overwrite`     | 默认 `false`，防止覆盖已有产物                                              |

仅需 ONNX 时，使用独立目录：

```bash
uv run --no-sync lerobot-export \
  --policy_path="$MODEL_PATH" \
  --output_dir="${EXPORT_DIR}_onnx" \
  --format=onnx --device=cpu
```

ONNX 使用 FP32、opset 18 和固定形状。TensorRT FP32 关闭 TF32；FP16 允许内部混合精度，浮点输入输出仍为 FP32。FP16 是否可用以精度验证结果为准。

完整模型包的主要文件：

```text
012000/
├── encoder.onnx              # 观测编码器
├── denoiser.onnx             # 单步 U-Net
├── encoder_fp32.engine
├── denoiser_fp32.engine
├── encoder_fp16.engine
├── denoiser_fp16.engine
├── assets/                   # 模型、调度器、处理器配置及统计量
├── manifest.json             # 输入输出接口、文件摘要、版本和设备信息
└── validation_report.json    # 验证命令生成，含精度与性能结果
```

按所选格式和精度生成对应文件。如有 ONNX 外部权重文件，也必须一起保留。复制部署产物时应复制整个模型包。TensorRT engine 与构建设备及软件版本有关，更换 GPU 型号或 TensorRT 版本后应重新构建。

## 3. 验证转换精度

验证命令加载现有产物，不会重新构建。参考比较仍需要原始训练检查点及本地数据集。

先用少量窗口检查流程：

```bash
uv run --no-sync lerobot-validate-export \
  --policy_path="$MODEL_PATH" \
  --export_dir="$EXPORT_DIR" \
  --device="$EXPORT_DEVICE" \
  --episodes=1 --windows_per_episode=1 --seeds='[0]' \
  --benchmark=false
```

少量窗口只用于排查环境和接口问题，不能替代完整验收。完整精度验证并评估性能：

```bash
OMP_NUM_THREADS=4 uv run --no-sync lerobot-validate-export \
  --policy_path="$MODEL_PATH" \
  --export_dir="$EXPORT_DIR" \
  --device="$EXPORT_DEVICE" \
  --warmup=10 --iterations=100
```

默认从检查点的 `train_config.json` 读取 `dataset.root`。若数据已迁移，或要明确选择验证数据集，在命令末尾添加：

```text
--dataset_root=/path/to/lerobot_dataset
```

切换模型时必须同时指定 `--policy_path` 和 `--export_dir`；省略参数会使用本文默认的 `dp_umi_v4/012000`。

仅验证上一步独立生成的 ONNX 包：

```bash
uv run --no-sync lerobot-validate-export \
  --policy_path="$MODEL_PATH" \
  --export_dir="${EXPORT_DIR}_onnx" \
  --device=cpu --backends='[onnx]' --benchmark=false
```

若只生成 TensorRT FP32，在完整验证命令中添加 `--backends='[tensorrt_fp32]'`。默认会请求 ONNX、TensorRT FP32 和 FP16 三个后端，应与实际生成的文件一致。

### 验证内容与通过标准

默认选取前四个满足长度要求的 episode，每个选择八个均匀分布的有效窗口，并额外验证各 episode 起点的首帧补齐及 reset。每个窗口使用种子 0、1、2，共 108 组采样，其中常规窗口为 96 组。

验证比较原生 PyTorch、导出包装的 PyTorch 及导出后端。各后端共享预处理输入和初始噪声，并对齐 DDPM 每一步的方差噪声。图像按训练语义解码，使用检查点保存的归一化统计量，不重复除以 255。

所有采样动作必须同时满足：

| 指标           | 门槛                 |
| -------------- | -------------------- |
| 位置欧氏偏差   | ≤ 1 mm               |
| SO(3) 旋转角差 | ≤ 0.5°               |
| 夹爪绝对差     | ≤ 0.01               |
| 输出           | 形状正确，无 NaN/Inf |

这些门槛衡量转换相对原模型的误差，不代表真实机器人任务成功率。默认 UMI 数据集已声明米、弧度和 0～1 夹爪单位。其他数据集缺少单位信息时，须先确认实际含义，再提供对应参数，例如：

```text
--position_unit=m --rotation_unit=rad --gripper_representation=normalized_0_1
```

不能把这些参数用于声明与数据不符的单位。当前物理验收支持每个 6D 位姿组对应一个夹爪维度，其他动作布局不能直接套用上述门槛。

报告保存在模型包的 `validation_report.json`，含组件最大绝对误差、RMSE，以及绝对动作误差的 mean/P95/max。重复验证会更新报告，需保留历史时先复制它。请求的后端失败时命令返回非零退出码，并保留报告；FP16 失败不会删除已通过的 FP32 产物或自动放宽阈值。

## 4. 阅读性能结果

GPU 性能测试顺序执行 PyTorch eager FP32、TensorRT FP32，以及通过精度验证的 TensorRT FP16。每个后端预热 10 次、测量 100 次，循环使用已解码的不同窗口，保持相同采样步数。

完整调用计时包含前处理、编码器、全部去噪步骤、后处理和必要传输，使用显式 CUDA 同步；排除文件读取、视频解码、首次加载和 engine 构建。报告中的 P50 是中位延迟，P95 反映较慢调用的延迟；加速比为 PyTorch P50 除以对应后端 P50。

阶段耗时单独测量。显存采用整卡每 10 ms 采样峰值，包含 TensorRT 原生分配、参考模型及其他进程，不能当作独立部署所需显存。评测时尽量使用空闲 GPU。

ONNX Runtime 使用 CPU 网络，其验证延迟单独列出；调度器在指定设备上执行，可能包含 CPU/GPU 传输，因此不参与 GPU 加速比。

### 默认模型的实际结果

2026-10-28，在 RTX 5090（`cuda:1`）上完成测试，保持 batch=1、DDPM 100 步、8 步动作块。软件版本：PyTorch 2.11.0+cu128、ONNX 1.22.0、ONNX Runtime 1.29.0、diffusers 0.39.0、TensorRT 10.13.3.9。

| 后端          | 完整调用 P50 |        P95 | P50 加速比 | 整卡显存采样峰值 |
| ------------- | -----------: | ---------: | ---------: | ---------------: |
| PyTorch FP32  |   1150.24 ms | 1150.72 ms |      1.00× |         2863 MiB |
| TensorRT FP32 |    363.40 ms |  363.65 ms |      3.17× |         3929 MiB |
| TensorRT FP16 |     77.82 ms |   86.30 ms |     14.78× |         3405 MiB |

108 组完整采样全部通过精度门槛：

| 后端          |    最大位置差 |  最大旋转差 |   最大夹爪差 |
| ------------- | ------------: | ----------: | -----------: |
| ONNX FP32     |  0.0001042 mm | 0.00001046° | 0.0000001192 |
| TensorRT FP32 | 0.00008697 mm | 0.00001145° | 0.0000001192 |
| TensorRT FP16 |     0.1452 mm |    0.02185° |    0.0002945 |

ONNX CPU 的 108 次验证调用 P50 为 3123.98 ms、P95 为 3159.04 ms；这是验证过程的观测延迟，不是另行预热并测量 100 次的 GPU 基准。

上述结果只适用于该模型、设备与配置。查看本地[完整报告](../../outputs/export/dp_umi_v4/012000/validation_report.json)，更换模型后重新验证。

## 5. 部署时保留的接口与处理步骤

默认模型的张量接口如下，其他模型以各自 `manifest.json` 为准：

| 阶段                        | 形状                |
| --------------------------- | ------------------- |
| 原始状态历史                | `[1,2,7]`           |
| 归一化后的相对状态          | `[1,2,10]`          |
| 编码器图像输入              | `[1,2,1,3,224,224]` |
| 编码器 conditioning         | `[1,148]`           |
| U-Net sample 输入与预测输出 | `[1,16,10]`         |
| U-Net timestep 输入         | `[1]`，int64        |
| 截取的相对动作块            | `[1,8,10]`          |
| 后处理后的绝对动作块        | `[1,8,7]`           |

推理顺序为：原始历史观测 → 相对位姿及归一化处理 → 编码器 → 调度器循环调用 U-Net → 截取动作 → 反归一化及绝对位姿恢复。

每个窗口的历史状态必须转换到最新观测的同一参考坐标系。前后处理共享位姿 anchor，当前窗口后处理完成后再处理下一窗口；跨 episode 时调用运行器 `reset()`。默认动作切片为 `[:,1:9]`。图像网络保留评估模式的 resize 和中心裁剪。

不能把原始 7 维状态直接送入默认模型的 10 维网络接口，也不能把 U-Net 单步预测直接作为机器人动作。模型包重新加载推理不需要原始权重，但仍需外部调度器和前后处理。运行器实现见 [runtime.py](../../src/lerobot/export/runtime.py)，更完整的技术说明见 [Diffusion 导出文档](../source/diffusion_export.mdx)。

## 6. 常见问题

| 问题                       | 处理方式                                                            |
| -------------------------- | ------------------------------------------------------------------- |
| 输出目录已存在             | 使用新目录；确认替换时添加 `--overwrite=true`                       |
| 缺少导出或 TensorRT 依赖   | 执行第 1 节安装命令，随后使用 `uv run --no-sync`                    |
| 数据集路径不存在           | 用 `--dataset_root` 指定当前本地数据目录                            |
| 缺少归一化统计量           | 找回完整检查点及处理器资产，不用验证数据重新估计统计量代替          |
| 找不到 FP16 engine         | 检查导出精度；仅构建 FP32 时验证指定 `--backends='[tensorrt_fp32]'` |
| TensorRT engine 不兼容     | 在目标 GPU 和匹配的软件环境下重新构建                               |
| FP16 精度失败              | 查看报告，使用已通过验证的 FP32 产物，不放宽门槛掩盖误差            |
| 未知单位或不支持的动作布局 | 明确数据单位和布局后再进行对应物理验收                              |
